# Decision log

Append-only. One entry per decision: date, sprint, decision, why. Sprints add entries when they change or refine `architecture.md` / `api-contract.md`.

| # | Date | Sprint | Decision | Why |
|---|---|---|---|---|
| D1 | 2026-09-26 | 00 kickoff | Expo + TypeScript strict + Expo Router; app lives in `fridgechef-app/` | Fastest path to an iOS React Native app on a Windows dev machine (Expo Go / EAS). Router maps 1:1 to mockup routes. |
| D2 | 2026-09-26 | 00 kickoff | The API sits behind a `FridgeChefApi` interface with `MockApi` (JSON fixtures) and `HttpApi`, selected by `EXPO_PUBLIC_API_MODE` | The user will supply the real endpoint + key later. Going live must be a `.env` change, plus mapper tweaks at most. |
| D3 | 2026-09-26 | 00 kickoff | Matching / scoring / pantry deduction stay on-device (port of mockup `logic.js`) | Deterministic, testable, works offline. The backend only detects and proposes recipes. |
| D4 | 2026-09-26 | 00 kickoff | Profile, pantry, scan session and cookbook are local-first (Zustand + AsyncStorage); no accounts in v1 | Matches the mockup. Accounts can come later without touching screens. |
| D5 | 2026-09-26 | 00 kickoff | UI copy rules: never show "AI", no play-button icons, hyphens not em dashes | Approved in the mockup design review (see `fridgechef-mockup/README.md` → Content rules). |
| D6 | 2026-09-27 | 01 bootstrap | Expo SDK 57.0.25 (React Native 0.86.3, React 19.2.3, TypeScript 6.0, Expo Router 57), from `create-expo-app@latest` default template. React Compiler + typed routes stay on (template defaults). | Latest stable at bootstrap. `npx expo-doctor` is clean on it. |
| D7 | 2026-09-27 | 01 bootstrap | App config lives in `app.config.ts` (no `app.json`). iOS bundle id `com.fridgechef.app` is a **placeholder**. | Typed config, room for env-driven values later. The real bundle id is needed before the first EAS build. |
| D8 | 2026-09-27 | 01 bootstrap | `config.ts` exports `parseConfig(raw)` (pure, testable) plus a frozen `config` parsed at import. Keys drop the `EXPO_PUBLIC_` prefix (`config.API_MODE`). Blank values count as unset, except `API_AUTH_SCHEME`, where an explicit empty value means "send the raw key". Invalid values throw `ConfigError` at startup. | Fail fast with a readable message. A `KEY=` line in `.env` must not break the defaults. |
| D9 | 2026-09-27 | 01 bootstrap | Lint = `eslint-config-expo` flat config + `eslint-config-prettier/flat` (no `eslint-plugin-prettier`). Formatting is checked separately with `npm run format:check` and is **not** part of `verify`. | Keeps `verify` exactly as specified and avoids line-ending (CRLF) lint failures on Windows. Prettier: single quotes, width 100. |
| D10 | 2026-09-27 | 01 bootstrap | Tests: `jest-expo` preset, RNTL 14 (async `render`, needs the `test-renderer` peer), AsyncStorage mock in `jest.setup.ts`, `@/` alias mapped in `jest.config.js`. Tests never live in `src/app/` (every file there is a route). App-level tests go in `src/__tests__/`. | Expo Router would treat a test file under `src/app/` as a route. |
| D11 | 2026-09-27 | 01 bootstrap | Git is initialised at the repo root, and the template's nested `fridgechef-app/.git` is removed. One root `.gitignore` covers the app. `react-native-web` is kept for a browser preview (`npm run web`). | One repo for mockup, sprints and app. A web preview is the only visual check an agent on this Windows machine can run without an iPhone. |
| D12 | 2026-09-27 | planning (user request) | All on-device data lives in **SQLite** via `expo-sqlite` (`fridgechef.db`): raw SQL in typed repositories under `src/db/repositories`, `PRAGMA user_version` migrations that are append-only. **Supersedes the AsyncStorage part of D4 and D10** (local-first and no accounts still stand). | The user asked for SQLite, which iOS and Android both ship. It gives relational queries, transactions for multi-row writes (confirm scan, cooking deduction), and real migrations. `expo-sqlite` is in Expo Go on SDK 57, so no development build is needed. |
| D13 | 2026-09-27 | planning (user request) | Mock backend data lives in a **separate SQLite file** (`fridgechef-mock.db`), opened only in mock mode, and seeded on first open from **typed TypeScript seed modules** (`services/api/mock/db/seed/*`). **No JSON fixture files** in the app. `MockApi` reads DTOs from SQLite, then runs the same Zod + mappers as `HttpApi`. **Amends D2** ("JSON fixtures" → mock SQLite DB; the interface and mode switch are unchanged). | The user asked for the mock data to come from the DB, not bundled JSON. TS seeds are reviewable, diffable and type-checked against the contract (chosen over a prebuilt binary `.db` file). A separate file keeps user data untouched when the mock is reset or when going live. |
| D14 | 2026-09-27 | planning | Zustand stays as the in-memory reactive layer: stores hydrate from the repositories at boot and actions write through. The `persist` middleware and `@react-native-async-storage/async-storage` (installed in Sprint 01) are removed in Sprint 04. | Keeps screens simple and synchronous to read, while SQLite is the only persistent store. One storage mechanism, not two. |
| D15 | 2026-09-27 | planning | Tests and `scripts/api-smoke.ts` use a `SqlDriver` port with a Node adapter on built-in `node:sqlite` (fallback: `sql.js`). `expo-sqlite` is imported only in `src/db/client.ts`. | `expo-sqlite` is a native module that doesn't run in Jest or plain Node. A port with the same method names keeps the production adapter trivial and lets tests run real SQL. |
